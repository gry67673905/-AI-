# 角色权限矩阵

## 身份模型

权限角色只有三种：

- `CITIZEN`：群众账号，可代表个人或企业发起办事；
- `STAFF`：工作人员账号，只处理分配部门/窗口内的任务；
- `ADMIN`：管理员账号，维护组织、人员、事项和知识，不代替工作人员审批。

`ApplicantType` 是群众申请主体类型，不是权限角色：`INDIVIDUAL`（个人）或 `ENTERPRISE`（企业）。个人/企业可通过本地演示验证码注册；工作人员只能由管理员创建；管理员只能由本地种子初始化。

公开事项和普通 AI 咨询允许匿名。历史、反馈、申请、私人办件查询、工作人员和管理员功能必须登录。

## Android 命令边界

WebView 不能传任意 URL 或 HTTP 方法。`PortalCommandPolicy` 先解析固定命令枚举，再按角色放行：

| 命令组 | 匿名 | 群众 | 工作人员 | 管理员 |
| --- | :---: | :---: | :---: | :---: |
| 登录/注册、事项搜索、公开咨询 | ✅ | ✅ | ✅ | ✅ |
| 草稿/表单/材料/提交、预约、缴费、核验、邮寄、历史/反馈/转人工 | — | ✅ | — | — |
| 待办认领、审核决定、人工咨询处理 | — | — | ✅ | — |
| 部门/窗口/人员/账号/事项版本/知识/审计/指标 | — | — | — | ✅ |
| 文档选择器、语音、TTS、窗口地图 | 由当前用例决定 | 由当前用例决定 | 由当前用例决定 | 由当前用例决定 |

原生边界继续做参数白名单校验：文档选择器只返回受支持类型；窗口地图只接受后端返回并再次校验的 `window_id`；语音只把最终文本发送到后端；Token 保留在原生 Keystore 存储中。

## 数据范围规则

### 群众

- 只能创建与本人 `ApplicantType` 一致的事项办件。
- 只能查看/修改自己的草稿、材料、办件、预约、支付、核验、邮寄、咨询和工单；只能取消自己的未终结预约、支付、邮寄和转人工工单。
- 已提交办件只能撤回，不能删除；草稿可丢弃但保留事件和审计。

### 工作人员

- 待办必须属于账号所分配部门；窗口分配可进一步收窄操作范围。
- 必须先成功认领才能作出决定；不能处理其他工作人员已认领的任务。
- 无事项配置、账号冻结或管理员权限。

### 管理员

- 可维护组织、窗口、人员、账号、事项版本和知识，重试失败知识任务、归档 ACTIVE/SUPERSEDED 任务，并读取脱敏审计/聚合指标。当前没有知识任务列表端点，`job_id` 来自上传响应或索引失败详情。
- 管理员 HTTP 权限不包含团队 RAG 导入、数据集切换或 DashScope 凭据；这些操作只由服务器 root 通过带显式付费确认的 `deploy/scripts/import-rag.sh` 执行。
- 不能使用工作人员审核接口；不能篡改已发布版本、不可变办件事件或审计事件。
- “删除”只实现为冻结、暂停、终止或归档，不清除历史。

## HTTP 失败语义

| 状态码 | 含义 | 典型场景 |
| --- | --- | --- |
| 401 | 未登录或令牌失效 | 缺少 JWT、过期、冻结后旧 token、refresh 已撤销 |
| 403 | 已登录但越权 | 跨用户材料、跨部门待办、管理员尝试审批 |
| 404 | 授权范围内资源不存在 | 未找到事项、办件、材料或任务 |
| 409 | 状态/版本/幂等/并发冲突 | 旧 `version`、非法状态跳转、预约冲突、任务已认领 |
| 422 | 输入、表单、材料或资格不完整 | 缺字段、缺材料、条件未能判断、不支持文件 |
| 502 | 模型调用失败 | DeepSeek 超时或失败，不伪造回答 |
| 503 | 核心依赖不可用 | PostgreSQL 或全栈就绪依赖失败 |
